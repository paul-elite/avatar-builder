Avatars for your users, and an editor they can keep using

Give every user a stable avatar from their id, with nothing to store. Let them make it theirs with an editor you can drop into any page. Every avatar is an SVG that carries its own look, so wherever it's saved, it can be opened and edited again.

HTTP API

Every response can be called from any origin and is cached at the edge. A given seed always gives the same image.

RequestReturns
GET /a/<seed>.svgThe avatar, image/svg+xml
GET /a/<seed>.json{ seed, generator, url, editUrl, config, document, svg }
GET /api/avatar?id=42The SVG for a user. id, email, username or name is hashed into the seed
GET /api/avatar?seed=x&hair=mop&skin=f3d2b9The generated look with some parts pinned
GET /api/avatar?avatar=<code>An exact look from a share code
POST /api/avatarOne avatar as JSON, for a user record (below)
POST /api/avatar with usersUp to 100 avatars in one call

Query options

size
16–2048 px, default 256.
format=json
The JSON response instead of the image.
download=1
Serve it as a file download.
any part
hair, eyes, mouth, skin, hairColor, bg… (see fields). Colours may leave out the #; none turns optional parts off.

Store the url (or nothing, and rebuild it from the user id), show it anywhere, and send people to editUrl to customise theirs.

From user data

Metadata only picks the seed. The first of id, userId, uid, sub, email (trimmed, lower-cased), username, handle or name is hashed, so raw values never appear in URLs. Pass seed to choose it yourself.

We never guess appearance from profile data. Name, gender, age or location don't change the face. If a user has made choices, send them as avatar (a partial config, a saved document or an SVG) and they win over the generated look. 
import { avatarFromUser } from 'avatar-builder';

const { seed, config } = avatarFromUser({ id: user.id, avatar: user.savedAvatar });

Prefer stable ids to emails: hashing hides an email from the URL, but someone who already knows the email can still compute its seed.

Portable format

Every SVG from the editor, the library or the API carries the description of its own look. That makes any copy of an avatar, on any website, a template: open it in the editor and the user carries on from that exact look.

<svg viewBox="-6 -16 195 195" data-avatar-format="avatar-builder/1" …>
  <title>Avatar</title>
  <metadata>
    <avatar-builder>{ "format": "avatar-builder", "version": 1,
                      "config": { "skin": "#f3d2b9", "hair": "mop", … },
                      "seed": "u_1dz58yaqlv3" }</avatar-builder>
  </metadata>
  <g data-layer="background">…</g>
  <g data-layer="avatar">
    <g data-part="skin">…</g> <g data-part="eyes">…</g> <g data-part="hair">…</g> …
  </g>
</svg>
  • document: { format, version, config, seed? }, the source of truth. Readers ignore anything else in the SVG.
  • layers and parts: named groups so the drawing can be inspected or styled. They're output only; edit the config, not the paths.
  • config: one flat object of named choices and hex colours (all fields).
import { readAvatar, loadAvatar, encodeAvatar } from 'avatar-builder';

readAvatar(svgString);   // → config. Also takes an <svg> element, a data URI, a document, JSON or a partial config
await loadAvatar(url);   // fetch an avatar SVG and read it
encodeAvatar(config);    // a short code for links: https://avatars.paulelite.com/?avatar=<code>

React

import { Avatar, AvatarBuilder, avatarFromUser } from 'avatar-builder';
import 'avatar-builder/styles.css';

// Show
<Avatar user={{ id: user.id }} size={40} />     // generated, stable
<Avatar value={user.savedAvatar} size={40} />   // a saved config, document or SVG

// Create or edit, starting from what they have
<AvatarBuilder
  template={user.savedAvatar ?? avatarFromUser(user).config}
  onChange={(config, { svg, document, code }) => save(document)}
/>

Safety & versioning

  • Every input is validated. Unknown shapes fall back to the default, colours must be plain hex (#abc or #aabbcc), and unknown fields are dropped. Avatars from users are safe to accept and re-render.
  • Seeds are stable per generator version. Responses include generator (now 1). If the generator ever changes, it ships as a new version, and existing seeds keep their faces.
  • Documents are versioned (format: "avatar-builder", version: 1). New fields only ever get added, so older avatars stay readable.
